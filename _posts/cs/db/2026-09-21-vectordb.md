벡터를 저장하고 빠르게 유사한 벡터를 찾는 DB임

- 자연어, 이미지, 음성 같은 데이터를 벡터로 변환해서 저장
- ‘유사한’ 벡터를 찾아내는 게 핵심 기능 (근처에 있는 걸 빨리 찾는 것)
- 보통 텍스트 임베딩 벡터 저장에 많이 씀

## **Vector DB를 왜 사용해야하나?**

- 흔히 사용하는 DB (RDBMS, NoSQL)는 텍스트 내용 그대로 검색하거나, 키워드 매칭으로 찾음.
    - Vector DB는 의미 단위로 검색해서 훨씬 유연하고 정확한 검색 가능.

## Vector Indexing(색인)

벡터들을 빠르게 찾을 수 있게 정리해 놓는 작업

벡터가 수십만, 수백만 개 쌓이면 그냥 하나하나 비교하면 시간이 매우 오래걸림.

→ 벡터들을 특정 구조(인덱스)로 정리해 놔서, 쿼리 벡터랑 비슷한 벡터를 더 빠르게 조회할 수 있도록 해둠

### **Indexing이 필요한 이유**

- Vector 값은 보통 수백 차원 이상임.
    - 벡터끼리 거리 계산(유클리디언, 코사인 등)을 직접 다 하면 시간이 매우 오래걸림.
    - Indexing을 하지 않을 경우 선형 탐색(모든 벡터 값을 비교)으로 비교하기 때문에 쿼리 하나에 드는 시간이 아주 오래 걸릴 수 있음.

### **Indexing 기법**

**Flat (Brute-force)**

- 모든 벡터를 다 비교하는 완전 탐색
- 정확도는 높지만 벡터가 많을수록 성능이 떨어짐

**HNSW (Hierarchical Navigable Small World Graph)**

- 그래프 기반 인덱스
- 벡터들을 노드로 연결한 그래프를 만듬
- 쿼리 벡터에서 가까운 노드를 빠르게 찾아가면서 탐색하는 방식
- 성능 좋고, 정확도도 높은 편

**IVF (Inverted File)**

- 벡터 공간을 여러 개 군집(클러스터)으로 나누는 기법
- 쿼리 벡터가 어느 군집에 가까운지 판단하고, 그 군집 내 벡터만 탐색함

**PQ (Product Quantization)**

- 벡터를 더 작은 부분으로 쪼개서 압축하는 방식
- 둘을 합쳐서 탐색 범위를 줄이고, 저장 공간을 줄이는 데 도움
- 속도 빠르고 메모리 효율적

### **Querying**

Indexing 방법에 따라 검색 방법도 달라짐

검색 쿼리를 실행했을 때 설정한 Indexing 알고리즘에 따라 유사도를 검색함

- Cosine Similarity
    - 두 벡터간의 각도를 측정하는 방법
    - 1에 가까울수록 유사한 벡터, -1에 가까울수록 정반대의 벡터임
- Euclidean Distance(L2)
    - 두 벡터간의 직선거리를 측정하는 방법
    - 0에 가까울수록 유사한 벡터, 값이 클수록 정반대의 벡터
- Dot Product(내적)
    - 두 벡터간의 내적을 측정하는 방법
    - 양수는 같은 방향, 음수는 반대방향의 벡터
